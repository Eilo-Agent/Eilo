# Security Policy

Do not report vulnerabilities in public issues. Contact the repository maintainers through a private GitHub security advisory where available.

Never commit tokens, passwords, private keys, seed phrases, personal data, or production configuration. If a secret is exposed, treat it as compromised: revoke or rotate it through the provider and inspect relevant audit logs. Do not reproduce it in issues or remediation notes.

Security-sensitive changes require threat analysis, least-privilege review, negative tests, and documented rollback steps.
