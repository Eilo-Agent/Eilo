# Contributing

1. Open an issue describing the problem, expected behavior, and acceptance criteria.
2. Keep changes focused and preserve existing behavior unless the change explicitly requires otherwise.
3. Update relevant instructions, workflows, and evaluations alongside behavior changes.
4. Never include secrets, personal data, proprietary prompts, or unlicensed material.
5. Run Markdown/link checks and all relevant evaluation scenarios.
6. Describe limitations and tests in the pull request.

Prefer clear language, explicit prerequisites, reproducible steps, and evidence-backed claims.
